## Формулировка задания

Практическая работа №5 по курсу ТРПО требует разработать оконное WPF-приложение
на C# (.NET), в котором обязательно задействованы:

- паттерн **MVVM** (разделение на Model / View / ViewModel);
- **команды** (интерфейс `ICommand`, собственная реализация `RelayCommand`);
- **стили** в XAML (`Style`, `DataTrigger`);
- **привязка данных** (`Binding`) между View и ViewModel.

Задание допускает выбор одного из предложенных вариантов приложения. Для этой
работы выбран **вариант 6 — клеточная модель «Игра "Жизнь"» (Conway's Game of
Life)**.

Вариант выбран сознательно: вариант 1 (приложение для изучения слов,
WordsTrainerApp) по этому курсу уже сдан другой студенткой, и чтобы не
повторять её приложение, для данной работы взят другой вариант из
утверждённого списка. Согласования с преподавателем это не требует, так как
вариант «Игра "Жизнь"» прямо присутствует в списке вариантов задания, а не
является «своим» предложенным вариантом.

### Требования к варианту «Игра "Жизнь"»

- определение параметров поля (число строк, столбцов, размер клетки) и
  параметров симуляции (скорость — интервал в мс между поколениями);
- ручное формирование начального состояния кликом по клетке (до запуска или
  когда симуляция на паузе);
- случайная генерация начального состояния с задаваемой долей живых клеток
  (0..1) через `Slider`;
- остановка процесса симуляции;
- пошаговый запуск (одна кнопка — один шаг) и непрерывный запуск с
  настраиваемой скоростью через `DispatcherTimer`;
- импорт/экспорт состояния поля в JSON-файл (размеры поля + состояние клеток).

### Правила игры «Жизнь»

Классические правила Конвея, соседство — 8-связное (все соседние по
горизонтали, вертикали и диагонали клетки). Поле — **не тор**: клетки за
пределами границ считаются мёртвыми, то есть края поля неактивны (это
простое и наглядное решение, явно допустимое формулировкой задания).

- живая клетка с 2 или 3 живыми соседями остаётся живой;
- мёртвая клетка ровно с 3 живыми соседями оживает;
- во всех остальных случаях клетка мертва (или умирает).

## Реализация

### Архитектура (MVVM)

```
Lab5/
├── Model/
│   └── GameField.cs        — чистая модель поля и правил игры, без UI
├── ViewModel/
│   ├── ViewModelBase.cs    — базовый класс с INotifyPropertyChanged
│   ├── RelayCommand.cs     — собственная реализация ICommand
│   ├── CellViewModel.cs    — ViewModel одной клетки (Row, Col, IsAlive, ToggleCommand)
│   └── MainViewModel.cs    — главная ViewModel приложения
├── Services/
│   └── FieldJsonService.cs — импорт/экспорт поля в JSON
├── App.xaml                — стили (Window, кнопки, ячейки)
├── MainWindow.xaml         — View (привязки, ItemsControl-сетка клеток)
└── MainWindow.xaml.cs      — только InitializeComponent() и DataContext
```

**Model (`GameField`)** — хранит `bool[,]` состояние клеток, размеры `Rows`/`Cols`,
и не знает ничего про WPF. Методы: `Clear()`, `Resize(rows, cols)`,
`Randomize(density, random)`, `CountAliveNeighbors(row, col)`,
`NextGeneration()` (один шаг по правилам Конвея), а также `ToFlatArray()` /
`LoadFrom(bool[])` для сериализации. `NextGeneration()` строит новое
поколение во временном массиве и подменяет им текущее состояние — это
гарантирует, что при подсчёте соседей клетки используются значения именно
текущего (ещё не изменённого) поколения.

**ViewModel (`MainViewModel`)** — связывает `GameField` с View:

- `ObservableCollection<CellViewModel> Cells` — плоский список клеток поля
  (по одному `CellViewModel` на клетку), к которому привязан `ItemsControl`;
- свойства `Rows`, `Cols` (с ограничением диапазона 5..60 — при бо́льших
  размерах `ItemsControl` с отдельными `Button` на клетку заметно тормозит),
  `Density` (0..1), `IntervalMs` (50..2000 мс), `Generation`, `IsRunning`,
  `AliveCount`, `StatusMessage` — все реализуют `INotifyPropertyChanged` через
  `ViewModelBase.SetField`;
- команды: `ToggleCellCommand`, `RandomizeCommand`, `ClearCommand`,
  `StepCommand`, `StartCommand`, `StopCommand`, `ExportCommand`,
  `ImportCommand`, `ResizeFieldCommand`.

Каждая клетка (`CellViewModel`) хранит свои координаты `Row`/`Col`, флаг
`IsAlive` и свойство `ToggleCommand`, в которое передана **та же самая**
команда `MainViewModel.ToggleCellCommand` (общая на все клетки — так проще
и экономнее, чем создавать отдельный `RelayCommand` на каждую из сотен
клеток). При клике кнопка клетки вызывает `ToggleCommand` с
`CommandParameter="{Binding}"`, то есть передаёт саму себя
(`CellViewModel`) в `MainViewModel.ToggleCell(CellViewModel? cell)`, которая
меняет `IsAlive` и синхронизирует соответствующую ячейку модели `GameField`.

Команда `ToggleCellCommand` (как и большинство других) доступна только пока
`!IsRunning` — редактировать поле руками можно до запуска или когда
симуляция стоит на паузе, как и требует задание. `CanExecute` пересчитывается
автоматически благодаря `CommandManager.RequerySuggested`, на которое
подписывается `RelayCommand.CanExecuteChanged`.

**Как работает каждая команда:**

| Команда | Что делает |
|---|---|
| `ToggleCellCommand` | Переключает `IsAlive` клетки-параметра и синхронно обновляет `GameField`. Доступна только когда `!IsRunning`. |
| `RandomizeCommand` | `GameField.Randomize(Density)` — случайно оживляет клетки с заданной долей, затем обновляет отображение и сбрасывает счётчик поколений. |
| `ClearCommand` | Очищает поле (`GameField.Clear()`), сбрасывает поколение. |
| `StepCommand` | Один вызов `GameField.NextGeneration()` — один шаг вперёд. |
| `StartCommand` | Включает `IsRunning`, запускает `DispatcherTimer` с интервалом `IntervalMs`; на каждый `Tick` выполняется тот же шаг, что и в `StepCommand`. |
| `StopCommand` | Останавливает таймер, снимает `IsRunning`. |
| `ExportCommand` | Открывает `SaveFileDialog`, сохраняет поле в JSON через `FieldJsonService.Export`. |
| `ImportCommand` | Открывает `OpenFileDialog`, читает JSON через `FieldJsonService.Import`, пересоздаёт поле и коллекцию клеток по данным файла. |
| `ResizeFieldCommand` | Пересоздаёт `GameField` с новыми `Rows`/`Cols` (значения из текстовых полей, зажаты в диапазон 5..60) и заново строит коллекцию клеток. |

При изменении `IntervalMs` во время работы симуляции новое значение сразу
применяется к уже запущенному `DispatcherTimer.Interval` — скорость можно
менять на лету.

### Стили и привязка данных

Стили объявлены в `App.xaml` (общие для всего приложения):

- `Style TargetType="Window"` — общий фон окна (`WindowBackgroundBrush`) и
  шрифт;
- `ControlButtonStyle` — стиль кнопок управляющей панели (закруглённые углы,
  акцентный цвет, эффект при наведении/недоступности через `Trigger` по
  `IsMouseOver`/`IsEnabled`);
- `CellButtonStyle` — стиль клетки поля: обычная клетка белая, а через
  `DataTrigger Binding="{Binding IsAlive}" Value="True"` цвет клетки
  меняется на зелёный, когда клетка жива. Это ключевая демонстрация
  `DataTrigger`, требуемая заданием.

Поле клеток реализовано как `ItemsControl ItemsSource="{Binding Cells}"` с
`ItemsPanelTemplate` = `UniformGrid Rows="{Binding Rows}" Columns="{Binding
Cols}"` — сетка автоматически перестраивается под текущие размеры поля.
`ItemTemplate` — `Button` с `Style="{StaticResource CellButtonStyle}"`,
`Command="{Binding ToggleCommand}"` и `CommandParameter="{Binding}"` (то есть
параметром команды выступает сам `CellViewModel` элемента).

### Импорт/экспорт JSON

`Services/FieldJsonService.cs` сериализует состояние через
`System.Text.Json` во внутренний DTO-класс `FieldDto { int Rows; int Cols;
bool[] Cells; }` (клетки — плоский массив, построчно, `Rows*Cols`
элементов). Диалоги выбора файла — `Microsoft.Win32.SaveFileDialog` /
`OpenFileDialog`. При импорте проверяется, что размеры в файле корректны и
что длина массива клеток совпадает с `Rows*Cols`, иначе выбрасывается
`InvalidDataException`, которая перехватывается во ViewModel и показывается
пользователю через `MessageBox`.

## Как запустить

```
dotnet run --project Lab5/Lab5.csproj
```

(либо через решение `КостинДА_5пр.sln`, либо конфигурацию VS Code из
`.vscode/launch.json`).

### Как пользоваться приложением

1. При необходимости задайте число строк/столбцов в полях «Строк»/«Столбцов»
   (допустимый диапазон 5..60) и нажмите «Пересоздать поле».
2. Сформируйте начальное состояние — кликните по нужным клеткам мышью, либо
   задвиньте ползунок «Плотность» и нажмите «Случайное заполнение».
3. Нажмите «Шаг» для одного поколения вперёд, либо настройте «Интервал (мс)»
   и нажмите «Старт» для непрерывной симуляции; «Стоп» останавливает её.
4. Пока симуляция запущена, поле нельзя редактировать кликом — сначала
   нажмите «Стоп».
5. «Экспорт в JSON» сохраняет текущее поле в файл, «Импорт из JSON»
   загружает ранее сохранённое состояние (размеры поля подстраиваются под
   файл автоматически).
